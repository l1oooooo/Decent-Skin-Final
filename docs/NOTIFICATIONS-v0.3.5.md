# Focus v0.3.5 notification audit

Baseline: v0.3.4 (`2daa10b`). Reviewed every production notification owner and its callsites. Source locations below refer to that baseline so the removed copy remains traceable. The v0.3.4 inventory is historical; this document supersedes its routine-feedback policy.

## Policy and shared producers

Normal machine state stays in the header and rolling brewing status. A successful direct adjustment stays in its control. There is no new toast style, timer, retry, or command behavior. Error processing, field validation, recipe journals, state freshness, physical controls and command gates remain intact.

| Message / trigger | Class | Decision and reason | Dismissal |
| --- | --- | --- | --- |
| Preparing for shot; Heating to your brew temperature, on telemetry | Duplicate machine-state information | Removed; header and rolling indicator already show it | No toast |
| Waiting for Decaid; Request acknowledged, from Home recipe/profile/utility changes and Sleep/Wake/reconnect | Redundant routine feedback | No immediate pending or success toast. Retain caught errors and watchdog. UI still waits for acknowledged writes and observed machine states | Failures 8s; no success card |
| Working… → Done., default `useOperation.run` | Redundant routine feedback | Quiet by default; explicitly supplied meaningful completions remain | Failures 8s |
| Sleeping + Wake action from machine gate | Duplicate machine-state information | Removed; full-screen Sleep and normal Wake remain | No toast |
| Other machine gates (stale readings, unavailable settings, unsupported operating mode, uncommon non-idle state) | Action warning | Keep changed-condition feedback; ordinary heating/preparing/brewing/utilities/sleep excluded | Existing info 4s / stale warning 8s; deduplicated |
| Water refill required / Low water | Safety/action warning | Keep confirmed-state latch, configured threshold, and non-refill-kit checks | Persistent; fresh confirmed resolution only |
| Machine needs attention | Safety/action warning | Keep fault latch | Persistent; confirmed resolution only |
| Machine disconnected + Reconnect | Important connection failure | Keep; outage is actionable, no connected-success counterpart | Persistent until fresh connection; no automatic retry |
| Scale unavailable during this shot | Safety/action warning | Keep only active scale-dependent operation (stop-at-weight or explicit blockOnNoScale) | Persistent until requirement/risk resolves |
| Ordinary scale disconnection | Duplicate machine-state information | Header only; unchanged | No toast |
| Device error and gateway error text | Important error | Keep original explicit errors; ordinary scale disconnect excluded; same active text deduplicated | 8s |
| Shot completed / Shot stopped manually / Shot ended | Meaningful completion | Keep once per shot ID | 4s; cleared on new shot/leaving view |
| Last received trace unknown / Brewing blocked / Review shot + Back to Home | Action warning | Keep review action and lifecycle | Persistent until review resolved |
| Still waiting for Decaid / outcome unconfirmed | Important uncertainty | Keep 45s watchdog, including quiet operations; no cancellation or replay | 8s; actual late result replaces/closes it |
| Owner-labelled daily settings Save, explicit Favorites Save, history Save/Delete/Export, profile Import/Export | Meaningful completion / error | Keep submitted-version and partial-save distinctions; these are explicit compound operations | Existing loading → 4s completion or 8s error |
| Inventory refresh/preferences read, editor record/lineage loading | Redundant routine feedback | Quiet pending state in owner hooks; content and busy controls show progress; errors/watchdog remain | No immediate loading toast |
| Advanced procedure, firmware, plugin install/update, transfer progress | Action warning / important operation | Keep named pending feedback and outcome; do not infer completion from acknowledgement or time | Pending until outcome or watchdog; existing result duration |
| NotificationMessage view-local failures | Important error | Keep unless specifically listed below; repeated telemetry does not reset an existing toast | 8s for error; original info 4s where unchanged |
